# The architectural signatures of Artemis

This page is a short map of the ideas emphasized across the public notes. None is claimed to be exclusive to Artemis. The product's character is in **combining them** in one coherent environment for business work.

| Design signature | What changes for the user | Read more |
| --- | --- | --- |
| One Workspace, one global conversation, shifting context | Move between work without managing disconnected chats | [Workspace](00-ONE-WORKSPACE.md) |
| Work is durable and independent of UI | Tasks may continue, wait and complete after the initiating message | [Execution](01-WORK-AS-THE-PRIMITIVE.md) |
| Compact capability access | Relevant permitted operations can be discovered without loading a giant tool catalog | [Capabilities](02-CAPABILITY-FABRIC.md) |
| Event Intelligence | Future conditions wake dormant work without endless model polling | [Events](03-EVENT-INTELLIGENCE.md) |
| Runtime-owned continuation | Known actions, compute, reasoning, waits and verification are distinct | [Continuation](04-CONTINUATION.md) |
| Adaptive cognition | Use the kind of intelligence the current operation really requires | [Cognition](05-ADAPTIVE-COGNITION.md) |
| Context as a computed view | Each question or operation receives relevant, scoped information | [Context](06-CONTEXT-AND-TRUST.md) |
| Evidence separate from authority | External observations inform decisions but do not grant permission | [Governance](07-AUTHORITY-AND-VERIFICATION.md) |
| Intent-shaped UI and software interaction | Users work with surfaces, artifacts and direct actions—not just chat replies | [Experience](08-EXPERIENCE.md) |
| Minimal-first team composition | Specialists appear when work requires them, not by default | [Teams](10-ADAPTIVE-TEAMS.md) |
| Separate skill, memory and knowledge boundaries | Methods, facts, tools and remembered preferences stay distinguishable | [Extensibility](11-SKILLS-AND-LEARNING.md) |
| Cases and automations across time | A business matter can persist across many completed tasks | [Cases](12-CASES-AND-AUTOMATION.md) |
| Operational explainability | Results can be inspected from evidence and work records rather than invented narratives | [Explainability](13-OPERATIONAL-EXPLAINABILITY.md) |
| Governed autonomy | Cost, recovery and control remain first-class as work scales | [Reliability](14-RELIABLE-AUTONOMY.md) |

**Scope:** this is a public conceptual map, not an end-to-end product availability claim. [What exists vs. what is being developed](STATUS.md).
